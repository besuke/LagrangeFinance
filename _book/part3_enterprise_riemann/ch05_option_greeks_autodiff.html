第III-5章 オプション・グリークス：GaussQuantとモンテカルロ・torchの比較

前章では、Bump & RevalueからAutomatic Differentiationへ発想を切り替え、偏微分、連鎖律、Computational Graph、Forward Mode、Reverse Modeを整理した。本章からは、その仕組みを実際の金融商品へ適用する。

本章では、解析的なBlack-Scholes式をtorchで書き直すのではなく、 既存の金融工学ライブラリであるGaussQuantを基準値として利用し、 同じEuropean OptionをMonte Carlo SimulationとRのtorchによって評価する。

比較する量は、

\[ \boxed{ NPV,\quad \Delta,\quad \Gamma,\quad Vega,\quad Theta } \]

である。

本章の中心は、

\[ \boxed{ \text{GaussQuant} \quad\longleftrightarrow\quad \text{Monte Carlo + torch + Automatic Differentiation} } \]

という比較である。

GaussQuantはQuantLibを利用した既存のPricing Engineとして使い、 torchではMonte Carlo PricingそのものをDifferentiable Computational Graphとして構築する。

III-5.3 モンテカルロによるOption Pricing

Risk-Neutral Measureの下で、配当利回り\(q\)を持つ株価過程を、

\[ \frac{dS_t}{S_t} = (r-q)dt + \sigma dW_t \]

とする。

満期\(T\)の株価は、

\[ \boxed{ S_T = S_0 \exp \left[ \left( r-q-\frac12\sigma^2 \right)T + \sigma\sqrt{T}Z \right] } \]

である。

ここで、

\[ Z\sim N(0,1) \]

である。

European CallのMonte Carlo価格は、

\[ \boxed{ \hat V = e^{-rT} \frac{1}{M} \sum_{m=1}^{M} \max \left( S_T^{(m)}-K, 0 \right) } \]

となる。

III-5.4 Common Random Numbers

GaussQuantとの比較や感応度の検算では、Monte Carlo Noiseをできるだけ抑える必要がある。

本章では乱数を一度だけ生成し、価格計算と感応度計算で同じ乱数を使用する。

torch_manual_seed(
  mc_seed
)

z_t <- torch_randn(
  n_paths
)

乱数\(Z\)は市場リスクファクターではないため、 requires_grad = TRUEは指定しない。

III-5.5 微分可能なモンテカルロ Pricing

Monte Carlo PricingをTensor演算だけで構成する。

european_call_mc_torch <- function(
    spot,
    strike,
    rate,
    dividend_yield,
    volatility,
    maturity,
    z
) {
  terminal_spot <- spot *
    torch_exp(
      (
        rate -
          dividend_yield -
          0.5 * volatility^2
      ) * maturity +
        volatility *
          torch_sqrt(maturity) *
          z
    )

  payoff <- torch_relu(
    terminal_spot -
      strike
  )

  torch_exp(
    -rate * maturity
  ) *
    torch_mean(
      payoff
    )
}

この関数では、

\[ S_0,\quad r,\quad q,\quad \sigma,\quad T \]

からTerminal Spot、Payoff、Discounting、Monte Carlo Averageまでが 一つのComputational Graphとして接続される。

III-5.8 Delta・Vega・Thetaの自動微分

Monte Carlo価格を最終出力としてReverse Mode Automatic Differentiationを行う。

first_grad <- autograd_grad(
  outputs = option_npv_mc_t,
  inputs = list(
    spot_t,
    volatility_t,
    maturity_t
  )
)

delta_mc <- first_grad[[1]]$item()
vega_mc <- first_grad[[2]]$item()

## maturity は残存期間 T なので、
## Calendar-Time Theta は -dV/dT とする。
theta_mc <- -first_grad[[3]]$item()

tbl_mc_first_order_greeks <- tribble(
  ~metric, ~value,
  "delta", delta_mc,
  "vega", vega_mc,
  "theta", theta_mc
)

tbl_mc_first_order_greeks

#>   metric    value
#>   <chr>     <dbl>
#> 1 delta   0.60086
#> 2 vega   38.900  
#> 3 theta  -5.4086

ここで、

\[ \Delta = \frac{\partial V}{\partial S_0}, \qquad Vega = \frac{\partial V}{\partial\sigma}, \qquad Theta = -\frac{\partial V}{\partial T} \]

をMonte Carlo Pricing Graphから直接取得している。

III-5.9 GammaとペイオフのKink

Gammaには注意が必要である。

European CallのPayoff、

\[ \max(S_T-K,0) \]

はStrikeでKinkを持つ。

Pathwise Automatic DifferentiationでこのPayoffをそのまま二階微分すると、 各Pathではほとんど至るところで二階微分がゼロとなるため、 Monte Carlo Gammaを単純な二階ADだけで安定して推定することはできない。

これは自動微分の失敗ではなく、Payoffの非滑らかさに由来する。

そこで本章ではGammaについて、Payoffを滑らかに近似した Smooth Payoffを用いて二階自動微分を確認する。

III-5.10 Smooth ペイオフによるGamma

正の部分、

\[ x^+ = \max(x,0) \]

を、

\[ \boxed{ x^+ \approx \frac12 \left( x+\sqrt{x^2+\varepsilon^2} \right) } \]

で滑らかに近似する。

\(\varepsilon\)を小さくすれば通常のCall Payoffへ近づく。

smooth_positive_part_torch <- function(
    x,
    epsilon
) {
  0.5 * (
    x +
      torch_sqrt(
        x^2 +
          epsilon^2
      )
  )
}

Smooth Payoffを使ったMonte Carlo Pricing Functionを定義する。

european_call_mc_smooth_torch <- function(
    spot,
    strike,
    rate,
    dividend_yield,
    volatility,
    maturity,
    z,
    epsilon = 0.25
) {
  terminal_spot <- spot *
    torch_exp(
      (
        rate -
          dividend_yield -
          0.5 * volatility^2
      ) * maturity +
        volatility *
          torch_sqrt(maturity) *
          z
    )

  payoff <- smooth_positive_part_torch(
    terminal_spot -
      strike,
    epsilon = epsilon
  )

  torch_exp(
    -rate * maturity
  ) *
    torch_mean(
      payoff
    )
}

Gamma用に新しい計算グラフを構築する。

III-5.12 モンテカルロ標準誤差

Monte Carlo価格には統計誤差が存在する。

価格の差を解釈するため、標準誤差も確認する。

with_no_grad({
  terminal_spot_se_t <- torch_tensor(
    spot_value
  ) *
    torch_exp(
      (
        risk_free_rate_value -
          dividend_yield_value -
          0.5 * volatility_value^2
      ) * maturity_value +
        volatility_value *
          sqrt(
            maturity_value
          ) *
          z_t
    )

  discounted_payoff_se_t <- exp(
    -risk_free_rate_value *
      maturity_value
  ) *
    torch_relu(
      terminal_spot_se_t -
        strike_value
    )

  mc_standard_error <- torch_std(
    discounted_payoff_se_t
  )$item() /
    sqrt(
      n_paths
    )
})

tbl_mc_error <- tribble(
  ~metric, ~value,

  "GaussQuant NPV",
  tbl_gaussquant_greeks |>
    filter(
      metric == "npv"
    ) |>
    pull(
      value
    )
)

III-5.13 自動微分の意味

本章で重要なのは、Black-Scholesの解析式を自動微分したことではない。

Monte Carlo Pricingを、

\[ \boxed{ \text{Risk Factors} \rightarrow \text{Simulation} \rightarrow \text{Payoff} \rightarrow \text{Discounting} \rightarrow \text{NPV} } \]

というDifferentiable Computational Graphとして構築したことである。

Forward計算では、

\[ S_0,\sigma,T \longrightarrow V \]

を計算する。

Reverse計算では、

\[ V \longrightarrow \Delta,\ Vega,\ Theta \]

へGradientを伝播する。

したがって、

\[ \boxed{ \text{Monte Carlo Pricing Engine} + \text{Reverse Mode AD} = \text{Differentiable Risk Engine} } \]

となる。

III-5.14 金利為替系デリバティブへの接続

European Optionでは、Risk Factorは少数であった。

しかし同じ考え方は、

\[ V = V \left( S_{FX}, \mathbf r_{JPY}, \mathbf r_{Foreign}, \sigma_{FX} \right) \]

というPRDCにも適用できる。

違いはComputational Graphの規模だけである。

European Option
    |
    v
Spot + Volatility
    |
    v
Monte Carlo
    |
    v
Delta / Vega / Theta

          ↓

PRDC
    |
    v
FX + JPY Curve + Foreign Curve + Volatility
    |
    v
Monte Carlo
    |
    v
FX Delta + JPY DV01 + Foreign DV01 + Vega

本章のMonte Carlo + torch実装は、 第III-7章で扱うPRDC Riskへの直接の準備となる。

III-5.15 まとめ

本章では、European Optionについて、

\[ \boxed{ \text{GaussQuant} \quad vs \quad \text{Monte Carlo + torch Automatic Differentiation} } \]

を比較した。

GaussQuantでは、QuantLibを利用して、

\[ NPV,\quad \Delta,\quad \Gamma,\quad Vega,\quad Theta \]

を取得した。

一方、torchではMonte Carlo PricingをTensor演算として構築し、 Reverse Mode Automatic Differentiationによって、

\[ \Delta,\quad Vega,\quad Theta \]

をPricing Graphから直接取得した。

GammaについてはPayoffのKinkによるPathwise二階微分の問題を確認し、 Smooth Payoffを用いた二階Automatic Differentiationを適用した。

この比較によって、自動微分の目的は解析公式を置き換えることではなく、

\[ \boxed{ \text{複雑なPricing Algorithmそのものを微分する} } \]

ことにあると分かる。

次章では、少数のRisk Factorを持つOptionから、多数のCurve Nodeを持つ金利商品へ問題の次元を拡張し、

\[ \boxed{ DV01 \rightarrow Bucketed\ DV01 \rightarrow GPS } \]

をYield Curve全体のGradientとして捉える。
