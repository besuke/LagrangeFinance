第III-2章 分散コンピューティングとジョブ・タスク制御

第III-1章では、金融工学と計算技術の発展を振り返り、一台のPC上でfuture / furrrを利用する並列計算を実装した。そこで使える計算資源は、あくまで一台のMachineに搭載されたCPU CoreとMemoryの範囲に限られる。

実務のRisk Calculationでは、Trade、Scenario、Monte Carlo Pathを多数の独立Taskへ分割し、それらを複数の計算資源へ配布する必要がある。本章では、PC内のParallel Computingから一段進み、Task生成 → Job Queue → Scheduler → Worker → Result Aggregationという分散コンピューティングの基本構造をRで表現する。

III-2.1 分散計算の基本構造

tbl_task <- tribble(
  ~task_ID, ~input_value, ~worker_group,
  1L, 10, "A",
  2L, 20, "A",
  3L, 30, "B",
  4L, 40, "B",
  5L, 50, "C",
  6L, 60, "C"
)

show_table_LFL(tbl_task)
#> # A tibble: 6 × 3
#>   tas_ID inp_value wor_group
#>    <int>     <dbl> <chr>    
#> 1      1        10 A        
#> 2      2        20 A        
#> 3      3        30 B        
#> 4      4        40 B        
#> 5      5        50 C        
#> 6      6        60 C
calculate_task_result_LFL <- function(task_ID, input_value, worker_group) {
  tibble(
    task_ID = task_ID,
    worker_group = worker_group,
    input_value = input_value,
    output_value = sqrt(input_value)
  )
}

III-2.2 リモート関数とワーカー実行

tbl_remote_request <- tbl_task |>
  transmute(
    request_ID = paste0(
      "REQ-",
      stringr::str_pad(task_ID, width = 3, pad = "0")
    ),
    task_ID,
    payload = purrr::pmap(
      list(task_ID, input_value, worker_group),
      \(task_ID, input_value, worker_group) {
        list(
          task_ID = task_ID,
          input_value = input_value,
          worker_group = worker_group
        )
      }
    )
  )

show_table_LFL(
  tbl_remote_request |>
    select(request_ID, task_ID)
)
#> # A tibble: 6 × 2
#>   req_ID  tas_ID
#>   <chr>    <int>
#> 1 REQ-001      1
#> 2 REQ-002      2
#> 3 REQ-003      3
#> 4 REQ-004      4
#> 5 REQ-005      5
#> 6 REQ-006      6
remote_calculate_task_LFL <- function(payload) {
  calculate_task_result_LFL(
    task_ID = payload$task_ID,
    input_value = payload$input_value,
    worker_group = payload$worker_group
  )
}
tbl_remote_result <- tbl_remote_request |>
  mutate(
    response = purrr::map(
      payload,
      remote_calculate_task_LFL
    )
  ) |>
  select(request_ID, response) |>
  tidyr::unnest(response)

III-2.5 まとめ

本章では、一台のMachine内部の並列化から、複数の計算資源を前提とする分散処理へ考え方を拡張した。重要なのは、計算関数そのものよりも、TaskをJobとして管理し、Queueへ投入し、SchedulerがWorkerへ配布し、結果を再び集約するというControl Planeである。

この構造があれば、Workerの実体はLocal Process、別Server、Container、Cloud Batch、HPC Clusterへ置き換えることができる。次章では、この計算基盤の上にTrade Data、Market Data、Calibration、Scenario、Pricing、Risk Aggregationを統合し、エンタープライズ金融計算システムとして組み立てる。
